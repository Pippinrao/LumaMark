# V1 UX 设计

本文件是 LumaMark V1 前台用户体验的主事实来源，描述 V1 默认界面、视觉目标、Markdown 编辑体验和验收标准。实现计划和代码改动必须先经过本文件审核通过后再展开。

## 范围

本设计只覆盖 V1 的核心桌面编辑体验：

- 默认布局。
- 顶部菜单。
- 左侧文件树和大纲。
- 右侧 Markdown 编辑区。
- 基础 Markdown live preview 体验。
- 亮色和暗色主题的视觉方向。
- UX 验收标准。

本设计不覆盖发布、安装包、商业官网、插件市场、云同步、AI 写作和完整 Typora Parity 后续阶段。

## UX 结论

V1 默认采用 **文件管理模式**。

界面由两个主要区域构成：

- 左侧：文件树和大纲共用一个侧栏，通过 tab 切换。
- 右侧：单一中央 Markdown 编辑区。

顶部采用桌面应用菜单栏，不采用显眼 toolbar。菜单项固定为：

- 文件
- 编辑
- 段落
- 格式
- 视图
- 主题
- 帮助

V1 不做三栏常驻布局。右侧不再常驻独立大纲栏。文件树和大纲不能同时占用横向空间。

V1 必须先通过 Web 高保真原型审核，再进入生产实现。当前原型入口：

- `docs/product/prototypes/v1-apple-file-mode/index.html`

该原型只用于 UX 审核，不是生产应用入口。

本地预览方式：

```powershell
pnpm exec vite --host 127.0.0.1 --port 4180
```

打开：

```text
http://127.0.0.1:4180/docs/product/prototypes/v1-apple-file-mode/
```

原型审核通过前，不得把这套 UX 合入生产 `AppShell`。

## 视觉原则

V1 视觉方向采用 Apple-like 的优雅桌面前端风格，但不复制 Apple 或 Typora 的专有素材、品牌元素或私有实现。

本轮高保真方向固定为：**quiet native workspace + liquid sidebar + paper-grade editor**。核心不是更炫，而是让第一眼像一个 2026 年的桌面 Markdown 写作 App：顶部低存在感、左侧安静可扫描、右侧文字优先。

必须满足：

- 轻量菜单栏。
- 清晰但克制的左右分区。
- 半透明材质感可以少量用于菜单、侧栏和顶部区域。
- 材质只用于 chrome、侧栏和浮层，不进入正文内容本身。
- 细边框、低阴影、舒适留白。
- 高质量字体栈和正文排版。
- 亮色主题干净明亮，暗色主题舒适低眩光。
- 交互反馈轻、准、快。
- 不用背景装饰、粗阴影、大色块或 hero 化标题制造“现代感”。

禁止满足于“能用但粗糙”。V1 的现代化必须由高保真原型、截图验收和用户审核共同证明。

## 成熟组件选型

V1 前台体验优先使用成熟组件，不手搓基础组件。

UX 高保真阶段不初始化 shadcn/ui。原因是当前原型只用于用户审核，仓库尚未有 `components.json`，并且本地 Node v25 下 shadcn CLI 存在兼容风险。高保真阶段继续使用当前已安装的成熟组件直接验证布局、材质、间距、字体、明暗主题和 Markdown 排版。

UX 审核通过后，生产实现前再初始化 shadcn/ui，作为统一设计系统和组件源码层。生产阶段优先选择 `radix` base，因为当前项目已经使用 Radix 的 Menubar、Tabs、Tooltip、Dialog 体系；preset 候选以 `nova` 为基线，`luma` 和 `vega` 只通过截图对比决定，不能因为名称或潮流直接选择。

当前 UX 组件选型：

| 能力 | 首选成熟组件 | 用途 |
|---|---|---|
| 顶部菜单 | `@radix-ui/react-menubar` | 文件、编辑、段落、格式、视图、主题、帮助 |
| 侧栏 tab | `@radix-ui/react-tabs` | 文件树和大纲切换 |
| tooltip | `@radix-ui/react-tooltip` | 图标按钮和辅助说明 |
| 左右分栏 | `react-resizable-panels` | 侧栏和编辑区 resize/collapse |
| 文件树 | `react-arborist` | 工作区树形浏览和长列表性能 |
| 图标 | `lucide-react` | 轻量一致的功能图标 |
| 命令面板 | `cmdk` | V1 后续命令面板，必须真实可用后才展示入口 |
| 长列表虚拟化 | `@tanstack/react-virtual` | 大纲、搜索结果、最近文件等长列表 |
| 编辑核心 | `CodeMirror 6` | Markdown 编辑、热路径、撤销重做和源码保真 |

若成熟组件无法满足目标，必须先写证据和替代方案，经项目所有者确认后才能自研。

允许自定义 CSS 的范围：应用外壳布局、桌面 chrome、侧栏密度、Markdown 排版、CodeMirror theme、文件树 row 视觉、resize handle、明暗主题 token、高保真原型专用视觉。

必须使用成熟组件的范围：Dialog、Menubar、Tabs、Tooltip、Command Palette、文件树、分栏、虚拟列表、表单基础控件、Select/Combobox、Switch/Checkbox/Radio、Toast、Alert、Empty、Skeleton、Badge。

## 布局

默认结构：

```text
┌──────────────────────────────────────────────────────────────┐
│ 文件  编辑  段落  格式  视图  主题  帮助                       │
├───────────────┬──────────────────────────────────────────────┤
│ 文件 / 大纲    │                                              │
│               │              Markdown 编辑区                 │
│ 文件树或大纲   │          内容居中，文档是视觉焦点             │
│               │                                              │
└───────────────┴──────────────────────────────────────────────┘
```

布局要求：

- 顶部菜单栏高度克制，接近原生桌面应用菜单，不做大按钮栏。
- 左侧侧栏默认显示，宽度建议 `240px` 到 `280px`。
- 左侧侧栏可以折叠，折叠后编辑区占据剩余空间。
- 右侧编辑区是唯一主工作区。
- 编辑内容在右侧区域内居中，正文最大宽度建议 `760px` 到 `820px`。
- 侧栏和编辑区之间只使用细分割线，不做重边框和卡片容器。
- 状态栏如保留，必须低存在感，只显示文件状态、字数、光标等必要信息。
- 窄桌面窗口下默认折叠侧栏，优先保证编辑区可读写，页面不得产生横向滚动。

## 顶部菜单

顶部菜单是主导航，不是工具栏。

菜单视觉要求：

- 小字号。
- 低高度。
- 无大面积背景色。
- hover/focus 反馈轻微。
- 不使用一排图标按钮替代菜单。
- 源码模式、侧栏显隐等命令优先从菜单触发；若原型为了审核提供快捷图标，必须是低存在感图标按钮，不得变成 toolbar。

菜单职责：

| 菜单 | V1 职责 |
|---|---|
| 文件 | 新建、打开文件、打开文件夹、保存、另存为、最近文件、退出 |
| 编辑 | 撤销、重做、剪切、复制、粘贴、查找 |
| 段落 | 标题层级、列表、引用、代码块、分割线 |
| 格式 | 加粗、斜体、删除线、行内代码、链接、图片 |
| 视图 | 文件侧栏、源码模式、大纲 tab、专注编辑区、缩放 |
| 主题 | 亮色、暗色、跟随系统 |
| 帮助 | 关于、文档、问题反馈入口 |

V1 可以先实现菜单外观和关键命令入口，但不能再把顶部做成显眼 toolbar。未实现的命令可以禁用或暂不显示，不能用假按钮制造完成感。

## 左侧侧栏

左侧侧栏由两个 tab 组成：

- 文件
- 大纲

文件 tab：

- 默认选中。
- 展示当前工作区目录。
- 优先展示 Markdown 文件和目录。
- 文件项高度紧凑，适合长列表扫描。
- 当前打开文件需要清晰高亮。
- 文件树空状态要简洁，不写教程式说明。

大纲 tab：

- 从当前 Markdown 标题生成。
- 展示标题层级。
- 点击标题跳转到对应位置。
- 当前可见标题可以高亮。
- 当前文档没有标题时显示低干扰空状态。

侧栏交互：

- 支持拖拽调整宽度。
- 支持折叠和重新打开。
- 支持专注编辑区：进入后收起侧栏、顶部菜单和状态栏，提供始终可见的可访问退出控件；退出后恢复进入前的侧栏状态。
- 折叠状态下不得破坏编辑区宽度和滚动位置。
- 文件树和大纲不能同时显示为两列。
- 搜索、命令面板、同步状态等入口如果出现在界面中，必须是真实可交互；未实现前不得摆放假入口。

## 编辑区

编辑区是 V1 体验成败的核心。

视觉要求：

- 文档内容是第一视觉焦点。
- 不使用卡片包住整篇文档。
- 正文排版接近正式文稿，而不是代码编辑器。
- 段落间距、标题层级、列表缩进、引用样式都要清晰。
- 光标、选区和输入反馈必须稳定、柔和、可见。
- 亮色主题以白色和中性灰为主，暗色主题以舒适深灰为主。
- 强调色只用于焦点、选中、链接和少量交互反馈。

排版建议：

- 正文行高建议 `1.65` 到 `1.8`。
- 正文字号建议 `15px` 到 `17px`。
- H1/H2/H3 需要明显层级，但不能过度夸张。
- 代码字体使用等宽字体，代码块和行内代码视觉区分明确。
- Mermaid 预览和代码块不能让页面产生突兀卡片堆叠感。

## Markdown Live Preview

V1 不能只满足于“源码上有 CSS class”。V1 的目标是 Typora-like live preview。

基本原则：

- Markdown 源文本始终是唯一真实数据。
- CodeMirror 持有 Markdown 正文和编辑热路径。
- WYSIWYG 只做视觉层，不把文档主数据转换成富文本 AST。
- 光标所在块允许显示必要源码符号，方便编辑。
- 非当前块优先呈现阅读态，Markdown 符号应隐藏或弱化。
- 源码模式必须能显示完整 Markdown 源文。
- 保存不得格式化、重排、吞空行或改变未编辑区域。

V1 必须覆盖的基础语法：

- 标题。
- 段落和换行。
- 粗体。
- 斜体。
- 删除线。
- 引用。
- 无序列表。
- 有序列表。
- 任务列表。
- 分割线。
- 行内代码。
- 代码块和语言标识。
- Markdown 链接。
- 图片引用基础预览。
- 表格基础展示和编辑。
- Mermaid fenced block。

当前块行为：

- 光标进入标题、列表、引用、代码块、表格或 Mermaid block 时，应优先保障源码可编辑。
- 光标离开后，应回到更接近阅读态的 live preview。
- 源码符号隐藏不能破坏光标定位、选区、复制粘贴、撤销重做和 IME 输入。

源码模式：

- 通过 `视图 -> 源码模式` 切换。
- 源码模式显示完整 Markdown 符号。
- 源码模式和 live preview 模式共享同一份文档数据和撤销历史。

## 美观标准

V1 的美观目标是“现代、安静、专业、长期写作不累”。

必须做到：

- 第一眼像桌面 Markdown 写作工具，不像后台系统或 IDE。
- 文档区域宽度、行距、标题层级和空白比例舒适。
- 左侧侧栏轻量，不抢编辑区注意力。
- 顶部菜单低存在感。
- 控件边框、背景、阴影都克制。
- 亮色和暗色主题都要独立打磨，不能只是反色。

禁止：

- 默认三栏常驻。
- 顶部大按钮 toolbar。
- 嵌套卡片式页面结构。
- 大面积装饰渐变、纯装饰色块或营销页式 hero。
- 为了显得现代而添加宣传型 eyebrow、演示状态文案或假功能入口。
- UI 文案解释显而易见的控件。
- 把功能堆满当成现代化。

## 国际化

所有可见文案必须支持简体中文和英文。

覆盖范围：

- 顶部菜单。
- 菜单项。
- 侧栏 tab。
- 文件树空状态。
- 大纲空状态。
- 状态栏。
- 设置项。
- 命令面板。
- 错误提示。
- tooltip。

菜单命名和命令分组不能通过字符串拼接实现，避免中英文语序差异带来问题。

## 可访问性和键盘

V1 必须保留键盘优先体验。

最低要求：

- 顶部菜单可键盘访问。
- 文件树和大纲可键盘导航。
- 编辑区焦点清晰。
- 侧栏折叠和切换有可访问名称。
- 所有图标按钮必须有 tooltip 或 aria label。
- 主题切换后对比度仍可读。

## 当前实现偏差

当前实现与本 UX 设计存在以下偏差，后续实现计划必须优先修正：

- 顶部是显眼按钮工具栏，不是菜单栏。
- 当前布局接近三栏工具台，右侧有独立大纲栏。
- 文件树和大纲没有收敛为左侧单侧栏 tab。
- 编辑区排版还偏 CodeMirror 默认文本区，不足以支撑高美观度目标。
- Markdown WYSIWYG 主要是浅层 decoration，不足以证明 live preview 体验完成。
- 现有自动化测试更多证明元素存在，缺少视觉回归和 Typora-like 交互验收。

## 验收标准

V1 UX 审核必须逐项满足：

- 默认首屏为顶部菜单 + 左侧文件/大纲 tab + 右侧编辑区。
- 右侧不出现常驻独立大纲栏。
- 顶部没有显眼 toolbar。
- 编辑区文档居中，最大宽度受控，文档是第一视觉焦点。
- 左侧侧栏可以折叠，折叠后编辑体验不受影响。
- 文件树和大纲只能在左侧 tab 中切换。
- 基础 Markdown live preview 支持本文件列出的全部基础语法。
- 光标所在块和非当前块有明确不同的源码符号显示策略。
- 源码模式可切换。
- 中英文文案完整。
- 亮色和暗色主题都通过截图审核。
- Playwright 视觉截图覆盖默认界面、侧栏文件 tab、侧栏大纲 tab、Markdown 综合文档、源码模式、暗色主题。
- 截图中不得出现文字溢出、控件重叠、假搜索入口、演示性状态文案或右侧常驻大纲。
- 高保真稿必须以真实 Markdown 文档内容作为视觉主体，不能把文档做成营销页或后台卡片。

自动化验收入口：

```powershell
pnpm quality:v1-ux-prototype
pnpm quality:v1-ux-screenshots
```

该测试锁定高保真原型的硬约束：顶部七菜单、文件/大纲双 tab、左侧侧栏、中央编辑区、正文宽度、侧栏折叠、窄桌面默认折叠、暗色主题、源码模式、无假搜索入口和无宣传型 eyebrow。

截图脚本会输出审核图片到 `test-results/v1-ux-screenshots/`，覆盖亮色文件树、亮色大纲、暗色文件树、暗色源码、侧栏折叠和窄桌面编辑区。

## 非目标

V1 UX 不追求：

- 完整复刻 Typora 的每一个菜单项和快捷键。
- 复制 Typora 的专有素材、品牌元素或私有实现细节。
- 插件系统。
- 多标签页。
- 云同步。
- 协作编辑。
- AI 写作面板。
- 完整导出发布工作流。

这些能力进入后续 Typora Parity 或 World-Class 阶段评估。
