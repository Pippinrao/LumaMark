# ADR 0026：可移植 Markdown 压缩包（.zip）导出与只读打开

状态：已接受。日期：2026-10-18。

## 背景

ADR 0025 为 LumaMark 增加了自包含 HTML/PDF 导出。用户还需要一种**仍可编辑**的可移植产物：把文档及其引用的图片一起打包，解压后其他 Markdown 工具无需 LumaMark 专用 URL 或绝对路径即可直接打开。

本决策之前仓库没有归档能力。文档图片由现有 asset service 解析，可能是相对路径、绝对路径、远程、草稿（`lumamark-draft://`）或 data URI。ADR 0025 已经拥有导出对话框、保存对话框、图片解析策略和冷路径渲染器。本决策只增加压缩包格式，不创建第二套导出 UI 或第二套图片解析实现。

## 决策

### 包格式

- 输出为标准 deflate `.zip`，根目录包含：`lumamark-package.json`、`<文档文件名>.md` 以及被引用的图片资源。
- 文档目录内的相对资源保持相对 POSIX 路径。绝对路径、逃出文档目录、草稿、下载的远程图片，以及文件名对 URL 解析有歧义的资源，统一放到 `lumamark-assets/<name>-<hash>.<ext>`。
- 清单是小型、前向兼容的描述文件：`format: "lumamark-markdown-package"`、`formatVersion: 1`、`entry`、`generator`。更高版本、非法清单、入口歧义或入口缺失一律拒绝，不做猜测。
- 其他 Markdown 工具会忽略清单。入口是 zip 根目录下的标准 Markdown 文件，因此把 zip 解压到文件夹后即可直接加载。

### 可移植图片目标

导出副本必须满足硬性不变量：每个图片目标只能是 `http(s)` URL、`data:` URI，或包内真实存在的相对 POSIX 路径。图片目标中不得残留 `asset://`、`lumamark-draft://`、`file://`、盘符、前导斜杠或反斜杠。

只有为了可移植性时才改写：

- 反斜杠改为 `/`；含空格/括号的目标使用尖括号形式；
- 相对路径首段含 `:` 时加 `./` 前缀，避免被当作 URI scheme；
- 含 `#`、`?`、`%`、`<`、`>` 的文件名移动到安全资源名；
- 绝对路径或逃出文档目录的本地图片复制进包并改写链接；
- 下载的远程图片与草稿图片复制进包并改写链接；
- `data:` 图片保持内联；`blob:` 与原始 HTML `<img>` 不打包，并给出可见警告。

图片目标之外的 Markdown 逐字节保留，包括 BOM、主导换行与逐行换行覆盖。

导出采用**失败关闭**：每个声明的本地/草稿/远程图片都必须成功解析、读取并写入；任一失败则整体失败，不提交 zip。这与 HTML 导出“渲染占位并继续”的策略刻意不同，因为缺资源的包不可移植。

### GUI 与复用

- `ExportKind` 增加 `package`；由现有 `useExportModel` 与 `ExportDialog` 负责准备/写入/完成/错误、警告、重试、保存对话框与 E2E 钩子。
- 文件菜单的 Export 子菜单与命令面板提供“导出为压缩包…”，不新增全局快捷键。
- Rust 侧复用 `resolve_local_image`、`resolve_draft_image`、`fetch_remote_image_bytes`；远程图片沿用现有的地址、重定向、内容类型与大小保护。
- 设置项 `images.downloadRemoteImagesOnExport` 默认关闭。HTML/PDF 导出保持原有的“始终下载”行为。

### 只读打开与解包

- 打开 `.zip` 时按 zip 指纹解压到缓存会话目录，然后把解压后的入口作为文档路径复用现有 `openPath` 流程。这样文档声明、最近文件覆盖、启动恢复、图片授权与文件监听都保持同一条代码路径。
- 包视图强制文档级只读锁，独立于显示模式。默认以阅读模式打开，但切换到源码或实时预览不得解除只读。
- Save/Save As 被禁用并在保存入口再次守卫；关闭、自动保存与恢复草稿都不会写入缓存副本。
- 最近文件与启动恢复记录 zip 路径，而不是临时入口路径。指向会话目录内其他 Markdown 文件的链接会被拒绝并提示“先解包”，防止绕过只读契约。
- “解包到文件夹…”把 zip 重新解压到 `<父目录>/<zip-stem>/`，拒绝覆盖已存在文件夹，并以普通可编辑文档打开入口。zip 本身永不修改。
- 不注册系统 `.zip` 关联；zip 只能通过打开对话框过滤器、命令行/“打开方式”、最近文件和启动恢复进入。

### 安全边界

- 解压前校验所有条目名：禁止绝对路径、`..`、反斜杠、盘符、控制字符、Windows 保留/非法名、大小写不敏感重复名与符号链接。
- 限制：4096 个条目、单条 512 MiB、总量 2 GiB、单条路径 200 字符、清单 64 KiB。加密与不支持的压缩方式拒绝。
- 导出端同样校验 archive path 与入口名，并在所有资源读取成功后才写出包。
- 会话目录位于应用缓存。打开包时清理超过 30 天且不在最近 20 个之内的会话。

## 被否定的备选

- **直接复制文档文件夹**：不能作为单一产物传输，也无法表示绝对路径或目录外资源。
- **通过虚拟 asset 协议提供 zip 条目**：需要第二套资源管线、blob 生命周期与编辑器图片解析改造。解压方案复用了现有管线与授权。
- **在 zip 内编辑并保存写回**：需要原子重写 zip、自动保存语义、冲突检测与资源监听。只读查看 + 显式解包是更小、更安全的首个契约。
- **用自包含 HTML 作为包**：不可编辑且丢失 Markdown 源；ADR 0025 已覆盖 HTML 导出。
- **打包所有本地链接与原始 HTML 图片**：解析、改写与风险远超本次图片资源范围。v1 明确边界并对原始 HTML 图片警告。

## 影响

- 新增 Rust 依赖 `zip`（仅 deflate）与 `package_service`/`package` 命令。
- 新增 `features/packages`，负责格式规划、导出规划、只读打开、解包与包会话状态。
- 编辑器增加独立于显示模式的文档级只读覆盖。
- 设置 v5 增加可选的 `images.downloadRemoteImagesOnExport` 字段；缺失值默认为 `false`，因此无需提升 schema 版本。
- 导出子系统增加第三种 kind，并复用其对话框与保存流程。

## 复审条件

若后续要求可编辑写回 zip、CLI 包导出、本地附件或原始 HTML 图片打包，或 12 MiB 远程图片上限成为产品阻塞，或缓存会话保留策略不足以支撑长时间会话，应重新评估本决策。
